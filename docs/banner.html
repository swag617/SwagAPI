SwagAPI
Shared library and core-services API that every Swag617 plugin builds on — one database pool, one economy bridge, one web server, one login.

Core Services
🗄️
Database Service
A single HikariCP connection pool shared by every dependent plugin — SQLite or MySQL, chosen once in config.yml. Async helpers keep queries off the main thread.
👤
Player Data Service
A cached SwagPlayerProfile per online player that any plugin can attach a PlayerDataModule to — load/save hooks fire automatically on join, quit, and auto-save interval.
🌐
Shared Web Panel
One embedded HTTP server hosts a dashboard, login system, and account management — dependent plugins mount their own module under /swagapi/<plugin>/ with zero auth code of their own.
📡
Cross-Plugin Event Bus
Publish/subscribe messaging between Swag plugins on named channels, without a hard compile-time dependency between them.

One Login, Every Plugin
Session-Gated Module Hosting
Every plugin that calls registerModule() gets its dashboard mounted under the same port, behind the same cookie session — no plugin re-implements its own login screen. /home lists every registered module live, /account manages panel logins, and /settings exposes auth options without touching YAML.

Utilities & Lifecycle
💰
Economy Service
Thin Vault wrapper with a safe no-op fallback when Vault or an economy plugin isn't present — dependent plugins never null-check Vault themselves.
💬
Messaging Service
Shared color code, placeholder, title, and action bar helpers built on Adventure Components, so every plugin's chat output looks consistent.
🔄
Update Service
Polls a JSON manifest, verifies SHA-256 checksums, and stages new jars for every Swag* plugin — applied automatically by a JVM shutdown hook on next restart.
